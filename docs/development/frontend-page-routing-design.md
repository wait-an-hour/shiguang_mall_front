# 时光商城网页端页面与跳转逻辑设计

## 1. 目标

本文归纳时光商城前端网页端需要设计的页面、路由分区、跳转逻辑和协作边界，方便多人并行开发。网页端建议按买家商城、商家工作台、平台管理后台三个业务入口组织，优先打通“商品 - 购物车 - 订单 - 库存 - 支付”核心交易链路。

### 2.2 网页端

## 4. 页面分区总览

| 分区 | 面向角色 | 核心目标 |
| --- | --- | --- |
| 买家商城 | 匿名用户、普通买家 | 浏览商品、购物车、下单、支付、确认收货 |
| 商家工作台 | 店铺管理员、商品运营、库存人员、订单客服 | 商品维护、库存入库、订单发货 |
| 平台管理后台 | 平台管理员、商品审核员 | 店铺、类目、品牌、商品审核和权限治理 |

## 5. 买家端页面设计

买家端核心目标是打通正向交易闭环。

| 页面 | 路由 | 主要功能 | 访问条件 |
| --- | --- | --- | --- |
| 首页 | `/` | 搜索入口、推荐商品、类目入口 | 匿名可访问 |
| 登录 | `/login` | 用户名密码登录 | 匿名可访问 |
| 注册 | `/register` | 创建买家账号 | 匿名可访问 |
| 商品列表 | `/products` | 关键词、类目、品牌、价格、库存筛选 | 匿名可访问 |
| 商品详情 | `/products/:spuId` | 商品图、属性、SKU、价格、库存、加购 | 匿名可访问 |
| 购物车 | `/cart` | 选中、改数量、删除、失效项提示 | 需要登录 |
| 结算页 | `/checkout` | 地址、商品分组、店铺备注、金额确认 | 需要登录且购物车有选中项 |
| 支付页 | `/payment/:tradeId` | 倒计时、余额、充值、确认支付 | 需要登录且交易待支付 |
| 订单列表 | `/orders` | 状态筛选、分页、查看详情、确认收货 | 需要登录 |
| 交易详情 | `/trades/:tradeId` | 父交易、地址快照、支付状态、子订单 | 需要登录 |
| 地址管理 | `/account/addresses` | 新增、编辑、删除、设默认地址 | 需要登录 |
| 个人资料 | `/account/profile` | 昵称、手机号、邮箱、头像 | 需要登录 |
| 钱包 | `/account/wallet` | 余额、充值、钱包流水 | 需要登录 |

### 5.1 买家端主流程

```text
首页 / 商品列表
  -> 商品详情
  -> 加入购物车
  -> 购物车
  -> 结算页
  -> 创建交易成功
  -> 支付页
  -> 支付成功
  -> 交易详情 / 订单列表
  -> 确认收货
  -> 订单完成
```

### 5.2 买家端关键跳转规则

- 未登录访问 `/cart`、`/checkout`、`/orders`、`/account/*` 时，跳转 `/login?redirect=原地址`。
- 登录成功后，如果存在 `redirect`，回到原页面；否则进入首页或用户中心。
- 商品详情页未选完整 SKU 时禁用“加入购物车”。
- 购物车失效商品不可选，但允许删除。
- 结算页提交前必须重新调用结算预览接口，价格或库存冲突时刷新页面数据并提示用户确认。
- 支付页倒计时只做展示，最终以服务端交易状态为准。
- 支付成功后跳转交易详情；支付失败留在支付页并展示失败原因。
- 订单操作按钮以后端返回的 `availableActions` 为准，前端不自行推进订单状态。

## 6. 商家端页面设计

商家端核心目标是支持商品维护、库存维护和订单履约。

| 页面 | 路由 | 主要功能 | 访问条件 |
| --- | --- | --- | --- |
| 商家首页 | `/merchant` | 当前店铺、待处理订单、商品概览 | 店铺成员 |
| 店铺切换 | `/merchant/shops` | 查看本人可管理店铺 | 店铺成员 |
| 店铺商品列表 | `/merchant/shops/:shopId/products` | SPU 查询、状态筛选、提交审核、上下架 | 商品权限 |
| 新建商品 | `/merchant/shops/:shopId/products/new` | 新建 SPU、SKU、属性 | 商品权限 |
| 编辑商品 | `/merchant/shops/:shopId/products/:spuId/edit` | 编辑商品、维护 SKU | 商品权限 |
| 库存管理 | `/merchant/shops/:shopId/inventory` | SKU 库存、可用库存、锁定库存、入库 | 库存权限 |
| 店铺订单 | `/merchant/shops/:shopId/orders` | 订单筛选、查看、发货入口 | 订单权限 |
| 店铺订单详情 | `/merchant/shops/:shopId/orders/:orderId` | 地址快照、明细、状态历史、物流 | 订单权限 |

### 6.1 商家端主流程

```text
商家首页
  -> 选择店铺
  -> 商品列表
  -> 新建 / 编辑商品
  -> 保存草稿
  -> 提交审核
  -> 平台审核通过
  -> 商家上架
  -> 库存入库
  -> 买家下单支付
  -> 店铺订单
  -> 订单详情
  -> 发货
```

### 6.2 商家端关键跳转规则

- 所有商家业务页面都通过 `shopId` 明确当前店铺上下文。
- 用户只能进入自己拥有有效成员关系的店铺。
- 切换店铺后，商品、库存、订单数据都必须重新拉取。
- 商品状态动作按当前状态展示：草稿可提交审核，审核通过后可上架，上架后可下架。
- 商品编辑保存后留在编辑页；提交审核成功后返回商品列表或展示状态变更。
- 发货只允许处理 `PENDING_SHIPMENT` 状态订单。
- 发货成功后刷新订单详情，并将订单状态展示为待收货。

## 7. 平台管理后台页面设计

平台端核心目标是维护基础资料、审核商品和管理店铺。

| 页面 | 路由 | 主要功能 | 访问条件 |
| --- | --- | --- | --- |
| 后台首页 | `/admin` | 平台概览、待审核数量 | 平台角色 |
| 店铺管理 | `/admin/shops` | 店铺列表、创建、编辑、启用、暂停、关闭 | 店铺管理权限 |
| 店铺详情 | `/admin/shops/:shopId` | 店铺资料、成员、状态 | 店铺管理权限 |
| 类目管理 | `/admin/categories` | 树结构、新增、编辑、启停 | 类目管理权限 |
| 类目属性 | `/admin/categories/:categoryId/attributes` | 属性模板 CRUD、排序 | 类目管理权限 |
| 品牌管理 | `/admin/brands` | 品牌新增、编辑、启停 | 品牌管理权限 |
| 商品审核 | `/admin/product-reviews` | 待审商品列表、审核筛选 | 商品审核权限 |
| 商品审核详情 | `/admin/product-reviews/:reviewId` | 查看变更内容、批准、拒绝 | 商品审核权限 |
| 用户权限管理 | `/admin/users` | 用户、角色、权限查看或维护 | RBAC 权限，二期可做 |

### 7.1 平台端主流程

```text
后台首页
  -> 店铺管理
  -> 创建店铺并分配商家管理员

后台首页
  -> 类目管理
  -> 类目属性模板
  -> 商家创建商品时使用

后台首页
  -> 商品审核
  -> 审核详情
  -> 批准 / 拒绝
  -> 商家商品列表状态变化
```

### 7.2 平台端关键跳转规则

- 平台后台默认面向桌面端，建议最小宽度 1280px。
- 类目、品牌、店铺状态会影响买家端商品是否可见。
- 商品审核批准后进入 `OFF_SHELF`，不自动上架，需要商家手动上架。
- 商品审核拒绝必须填写拒绝原因。
- 平台端页面需要基于平台角色和权限控制菜单显示。

## 8. 全局路由守卫设计

### 8.1 路由 Meta 建议

```ts
{
  path: '/merchant/shops/:shopId/products',
  component: () => import('@/views/merchant/ProductListView.vue'),
  meta: {
    requiresAuth: true,
    area: 'merchant',
    permissions: ['shop:product:manage']
  }
}
```

### 8.2 守卫流程

```text
进入页面
  -> 是否需要登录？
    -> 未登录：跳转登录页
  -> 是否已加载 auth/me？
    -> 未加载：请求当前用户信息
  -> 是否有平台角色 / 店铺权限？
    -> 无权限：跳转 403 页面
  -> 是否访问不存在资源？
    -> 跳转 404 页面
  -> 放行
```

### 8.3 通用页面

| 页面 | 路由 | 用途 |
| --- | --- | --- |
| 403 | `/403` | 无权限 |
| 404 | `/404` | 页面或资源不存在 |
| 500 | `/500` | 系统错误 |
| 登录过期 | 复用 `/login` | Token 失效后重新登录 |

## 13. 开发顺序建议

1. 建立基础工程、路由、布局和登录态。
2. 实现 API Client、统一响应处理和 Mock 数据。
3. 实现买家端商品列表和商品详情。
4. 实现购物车、结算、创建订单和支付。
5. 实现订单列表、交易详情和确认收货。
6. 实现商家商品、库存和发货页面。
7. 实现平台店铺、类目、品牌和商品审核页面。
8. 补充权限控制、异常状态、端到端验收测试。

## 14. 总结

网页端建议采用 Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router。页面按买家商城、商家工作台、平台管理后台拆分，第一期优先完成正向交易闭环，后续再扩展营销、售后、物流轨迹和数据看板。核心不是页面数量，而是先保证“商品 - 购物车 - 订单 - 库存 - 支付”链路可演示、可联调、可验收。
